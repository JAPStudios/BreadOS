# BreadOS

BreadOS is a freestanding 32-bit x86 operating system with its own kernel and native system software. Omarchy is a feature reference; BreadOS does not use Linux, Arch, systemd, pacman, Wayland, Hyprland, Quickshell, D-Bus, or the Linux userspace ABI.

## Implemented

- Multiboot v1 boot through GRUB, VGA fallback, and validated 24/32-bit RGB framebuffer support.
- Native framebuffer drawing, glyph rendering, and graphical text output.
- GDT, TSS, IDT exceptions, remapped PIC, 100 Hz PIT, physical frame allocator, bootstrap paging, and a hardened fixed kernel heap with allocation canaries, guarded block metadata, allocation/free poisoning, and an integrity checker.
- PS/2 keyboard IRQ1 input, PS/2 mouse IRQ12 packet decoding, bounded input queues, and serial diagnostics.
- RAM filesystem and ATA PIO-backed BreadFS v1, exposed through a mounted native VFS. The VFS mounts the active root backend at `/`, device nodes at `/dev`, and live system information at `/proc`; it provides file handles, sequential reads/writes, seeking, metadata queries, directory enumeration, file/directory operations, plus console, serial, null, and zero devices. Shell, desktop file browsing, and executable loading use the VFS. The persistent volume has 16 metadata entries and 15-character paths. Text files hold up to 255 bytes; binary files have separate 65,535-byte extents and require a disk of at least 4,096 sectors (2 MiB). Binary writes are not yet transactional.
- Round-robin scheduler for three kernel tasks plus up to five independently scheduled ring-3 processes. Each user process has a private page directory, mapped ELF load segments, a user stack, a dedicated kernel interrupt stack, and an `int 0x80` write/exit/IPC syscall path. User tasks exchange bounded 64-byte messages through eight-slot nonblocking mailboxes; user pointers are validated against mapped user pages before copying. The scheduler preserves each process interrupt frame and address space; exit and recoverable user exceptions move the process to a zombie state, then reclaim its page frames and stacks after switching away from its address space.
- Native framebuffer desktop with draggable floating windows, four workspaces, dwindle/scroll/floating layouts, a dock, mouse interaction, and Shell, Files, Appearance, System, Notifications, and Clipboard windows. The Files window previews selected BreadFS text files.
- Twenty-three native color palettes ported from Omarchy theme data. Theme selection persists in BreadFS across reboots.
- Searchable command palette, 16-entry shell history, and a native notification service with a 16-entry history, stacked alerts, dismissal, snoozing, and Do Not Disturb.
- Native clipboard history with sensitive-content exclusion and compiler-resistant memory wiping when clipboard contents are cleared, plus timer-based reminders delivered through the notification service.
- Configurable desktop idle screensaver with a persistent timeout; keyboard or mouse activity wakes it. This is not an authenticated screen lock.
- Native privacy permission policy for camera, microphone, location, network, Bluetooth, USB, and sensors; permissions default to denied and persist in BreadFS. This is a policy registry, not hardware isolation: device drivers and general user processes are not yet wired to enforce these permissions.
- Host regression tests for filesystem metadata, binary storage, VFS mounts and file operations, ELF validation, PCI and audio helpers, keyboard input, mouse packets, task switching, user-task lifecycle, IPC queues, framebuffer rendering, themes, command search, notifications, clipboard history, reminders, privacy settings, secure memory, and idle timeout behavior, plus a QEMU boot/persistence smoke test. Core IPC, VFS, ELF-loader, and filesystem host tests also run under AddressSanitizer and UndefinedBehaviorSanitizer in CI.

## Shell commands

`help`, `menu [SEARCH]`, `history`, `heapcheck`, `theme [NAME]`, `desktop`, `notify TEXT`, `notifications`, `snooze INDEX TICKS`, `dismiss INDEX`, `dnd [on|off]`, `clipboard copy|sensitive|paste|history|clear`, `remind TICKS TEXT`, `reminders`, `remind clear`, `idle [TICKS|off|status]`, `privacy [list|CAPABILITY on|off]`, `beep FREQUENCY [DURATION_TICKS]`, `about`, `video`, `userdemo`, `exec PATH`, `memory`, `storage`, `uptime`, `tasks`, `ps`, `ls [PATH]`, `mkdir PATH`, `rmdir PATH`, `cat PATH`, `write PATH TEXT`, `mv SOURCE DEST`, `rm PATH`, `clear`, `reboot`, and `halt`. The `exec` command loads an ELF32/i386 binary through the VFS binary-file API. `ps` lists live user task IDs. User-mode syscall registers are: `eax=1` writes the low byte of `ebx`; `eax=2` exits with `ebx` as the status; `eax=3` sends a message with `ebx` target, `ecx` user buffer, and `edx` length; `eax=4` receives into the `ebx` user buffer with `ecx` capacity and returns the sender in `edx`; `eax=5` returns the current task ID; `eax=6` writes a user buffer to the console (`ebx` pointer, `edx` length, maximum 256 bytes) and returns the byte count; `eax=7` opens a VFS path (`ebx` path, `ecx` flags) and returns a task-owned handle; `eax=8` closes the handle in `ebx`; `eax=9` reads from handle `ebx` into user buffer `ecx` up to `edx` bytes; `eax=10` writes up to `edx` bytes from user buffer `ecx` to handle `ebx`; `eax=11` seeks handle `ebx` using signed offset `ecx` and origin `edx` (0=start, 1=current, 2=end). File I/O transfers are limited to 256 bytes per call. Handles are task-owned and discarded when a process is reaped; the kernel VFS provides four independent handles per task. IPC send and receive are nonblocking.

The `beep` command plays a tone through the PC speaker using PIT channel 2 (20–20,000 Hz; duration in 100 Hz timer ticks); this is basic mono tone output, not a sound-card, microphone, mixer, or audio-visualization stack. The `heapcheck` command validates the kernel heap block chain, metadata guards, and live allocation canaries. The allocator refuses to free allocations whose canaries fail validation. The `idle` command configures the desktop screensaver timeout in PIT ticks (100 ticks = one second, default five minutes; `off` disables it). The screensaver wakes on keyboard or mouse activity and is not a security lock screen. The `theme` command lists or applies the 23 palettes. `menu` searches the built-in command registry. `notify` creates a system notification; notification indexes are newest-first and snooze durations use PIT ticks (100 ticks = one second). `desktop` requires an RGB framebuffer of at least 320×240. Press `q` to return to the shell. Desktop shortcuts: `t` Appearance, `f` Files, `s` System, `e` Shell, `n` Notifications, `c` Clipboard, `d` toggle Do Not Disturb, `l` cycle layouts, `,`/`.` scroll the scrolling layout, `1`–`4` or `[`/`]` switch workspaces.

## Native user applications

The i386 user-mode SDK is in `user/include/breados/syscall.h`. It provides inline wrappers for console output, process exit, task IDs, nonblocking IPC, and task-local VFS file operations. `user/linker.ld` places application segments in the user address range and separates read/execute text from read/write data. `make user-apps` builds five ELF32 programs: `hello`, `guard`, `victim`, `attacker` and `wxguard`; `make test` validates each with the kernel's ELF loader. On a new run image, `make run` installs all five into BreadFS. `exec hello` runs the output demo. `exec guard` attempts a supervisor-memory write and should fault only that process. The `victim` and `attacker` pair test process-to-process isolation: the attacker writes to its own mapping at the victim's virtual data address, then signals the victim through IPC; the victim verifies its private value is unchanged. `exec wxguard` writes to a writable data page and then attempts to execute it; the PAE/NX page fault must terminate only that process. Executable ELF pages are read-only, while writable data and stack pages are non-executable. CPUs without PAE/NX can boot the kernel but user-process execution is disabled. Other applications must likewise be present in the mounted VFS before `exec PATH` can load them.

## Build and test

On Debian/Ubuntu:

```sh
sudo apt-get update
sudo apt-get install build-essential binutils gcc-multilib grub-pc-bin grub-common xorriso mtools qemu-system-x86
make clean iso
make test
make run
```

## Remaining Omarchy feature work

The current desktop is kernel-rendered; its windows are not yet independent user-mode applications. The kernel now supports independently scheduled ELF32/i386 user processes with per-process kernel stacks, exit handling, deferred resource reclamation, and bounded nonblocking IPC. The VFS provides independent per-task file descriptor tables. Kernel tasks retain full filesystem access; unprivileged user processes can read the root filesystem but can create, modify, rename, and remove files only inside the shared `/tmp` namespace. User processes also retain access to explicitly exposed `/dev` devices and read-only `/proc` views. VFS mount and unmount operations validate mountpoints and refuse to detach mounts with open handles or nested mounts. Per-user accounts, configurable POSIX permissions, symlinks, independent storage-volume drivers, and broader storage-driver support remain. Per-monitor workspaces, multi-display management, advanced window effects, cross-application clipboard integration, full settings panels, language/localization coverage, authenticated screen locking, screenshot/recording, full sound-card audio, networking, Bluetooth, USB, broad hardware support, an installer, secure package management, transactional updates, snapshots, and the remaining Omarchy application/workflow features still require native implementation. The privacy permission registry is not yet enforced by device drivers or a general user-process security boundary.

## Storage safety

`make run` uses the disposable `build/breados-disk.img` emulator image. The first `make run` creates a 16 MiB BreadFS image containing `/hello`, `/guard`, `/victim`, `/attacker` and `/wxguard` when no disk image exists; an existing image is preserved. The QEMU smoke test creates a fresh test image with all five applications, executes them, checks supervisor and process-to-process isolation, then verifies that the volume remounts on a second boot. Do not point QEMU at a physical drive or an image containing data that must be preserved. BreadFS leaves unrecognized disk formats unchanged and falls back to the RAM filesystem.
