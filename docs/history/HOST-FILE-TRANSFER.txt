NEXT FILES: IMPORT AND EXPORT REAL HOST TEXT FILES

These are Python host-side tools, not kernel modules. No Makefile or kernel
change is needed. They target ONLY the integrated starter's BSF2 snapshot.
They do not access GitHub, cloud accounts, physical disks, or arbitrary OS
filesystems. Never run them against a physical drive.

FIRST: boot the integrated starter, enter save, then close QEMU completely.
A blank image is not accepted. If another image format is detected, stop:
this tool is not an importer for earlier prototypes or unrelated projects.

Place disk_tools.py beside disk.img. All commands run on the BUILD COMPUTER.
The --offline flag is an acknowledgement, not automatic emulator detection.

LIST IMAGE ROOT
  python3 disk_tools.py --offline ls /

CREATE A FOLDER IN THE IMAGE (only if not already present)
  python3 disk_tools.py --offline mkdir /Documents

IMPORT A HOST FILE INTO THAT FOLDER
  python3 disk_tools.py --offline import notes.txt /Documents/notes.txt

MOVE IT OUT OF THE FOLDER, STILL INSIDE THE IMAGE
  python3 disk_tools.py --offline mv /Documents/notes.txt /

EXPORT FROM THE IMAGE TO A NEW HOST FILE
  python3 disk_tools.py --offline export /notes.txt exported-notes.txt

Use --image PATH before the subcommand to choose another dedicated image.
Quotes work through the host shell for filenames containing spaces.

After host-side edits, boot QEMU and enter load to read the changed snapshot.
Do NOT enter save first: that would replace the imported snapshot with the
kernel's current RAM state. Exporting reads the last saved disk snapshot,
not unsaved live RAM files. Export copies; it does not delete the image file.

Limits: ASCII filenames/text, no NUL bytes, max 1023 bytes per file,
31-byte names, 63 user entries, no overwrite or recursive import/export.
For imports, give the full destination filename, not just a folder.

Every image edit creates a separate uniquely named backup, writes a temporary
file beside the image, then replaces the original. Keep backups. This is
not a general crash-recovery guarantee; directory metadata is not fsynced.
Changes from concurrently running QEMU are unsafe; CLOSE IT FIRST.

Tests: python3 -m unittest -v test_disk_tools.py
These test host-side image operations, not a booted kernel or real ATA I/O.
